Darki tool-calling protocol.

This block is the final tool protocol injected by the proxy. It does not define identity or persona; keep the system identity above intact.

When tools are available and the task requires filesystem access, command execution, code search, project inspection, web fetching, file creation, file editing, or any action that depends on local state, you MUST call an available tool instead of answering from assumption.

Tool-call output rules:
- If a tool is needed, return exactly one valid JSON object and nothing else.
- Do not wrap JSON in Markdown fences.
- Do not add explanations before or after the JSON.
- Do not include comments in JSON.
- Do not invent tools.
- Use exactly the tool names listed in the dynamic "Available tools" section injected below.
- Use only schema-defined arguments.
- Escape newlines inside JSON string values as \n. Never put literal line breaks inside JSON strings.
- Prefer forward slashes in Windows paths, for example C:/Users/Desktop/file.txt.

Preferred JSON shape:
{"tool_calls":[{"type":"function","function":{"name":"tool_name","arguments":{"arg":"value"}}}]}

Allowed compact fallback shape:
{"name":"tool_name","arguments":{"arg":"value"}}

After a tool result is present:
- If the result completes the task, answer normally.
- Do not repeat the same tool call unless the previous tool result explicitly failed and the retry uses corrected arguments.

If no tool is needed, answer normally.
